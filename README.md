#### 🏢 dive-BTP — 실기업 데이터의 "믿을 수 없는 컬럼"을 걸러내는 일

**DIVE 2026 부산 글로벌 데이터 해커톤** — 부산광역시 주최 / 부산테크노파크(BTP) 주관,
**부산테크노파크 × 한국평가데이터(KODATA) 발제 트랙**에 4인 팀으로 참가했습니다.

발제 주제는 BTP 실무진이 제기한 **기업 선정·심사 과정의 한계** — ① 신청기업이 제출한 서류만으로는
실제 역량을 검증할 객관적 지표가 없고 ② 부서별 심사가 분절돼 중복·반복 지원을 즉시 파악하기 어렵다는 것.
KODATA의 기업 재무·고용·특허·정부R&D 데이터와 BTP의 사업지원 이력을 받아,
심사 담당자가 **서류상 역량과 실제 역량을 대조**할 수 있는 스코어카드 도구를 만들었습니다.
저는 **기술력 축(특허·정부R&D·인증)의 데이터 파이프라인과 심사 리포트 기능**을 맡았습니다.

- **원장을 진실로 삼는 재집계** — 제공된 특허 "누적" 집계 컬럼이 시간에 따라 감소하는 걸 확인하고
  집계값을 폐기, 특허 원장에서 직접 재계산. 상표·디자인권을 걸러 **R&D 산출물만** 기술 지표에 반영
- **중복·표기 편차 정규화** — 기준일자별 스냅샷 탓에 같은 정부과제가 여러 행으로 잡히는 구조를 파악해
  과제 단위로 dedup(안 하면 수주 실적이 부풀려짐). 지역·부처명 표기 편차는 별칭 매핑을 config로 분리
- **잘못된 파생지표를 걷어냄** — 출원일 파싱 오류로 특허 존속기간이 전건 만료로 오판되는 걸 발견,
  경과년수로 재계산하는 대신 원본 유효여부를 신뢰하도록 판정 기준을 바꾸고 근거를 설계노트로 남김
- **미분류 없는 기술 도메인 매핑** — LLM 추론에 의존하던 분류를 업종코드 기반 **결정론적 크로스워크**로
  전환해 재현 가능하게 만들고 미분류를 제거
- **심사 리포트 빌더** — 스코어카드 항목을 골라 PDF/Word/CSV로 내보내는 편집기 (다중 기업 일괄 처리)

> 판단 기준은 전부 `docs/*_설계노트.md`에 "이 데이터가 이래서, 이렇게 방어했다" 형태로 기록했습니다.
> 규칙으로 100% 풀리는 문제(중복 지원 탐지 등)에는 모델을 얹지 않는다는 원칙을 팀 차원에서 지켰습니다.

#### 📈 StockView — 예측이 안 된다는 걸 검증하고, 제품을 다시 정의한 프로젝트

- 근거별 IC 백테스트 + 로지스틱 다변량 학습으로 **시간순(walk-forward) 검증**을 돌린 결과,
  **기술적·가격 지표만으로는 단기 방향을 못 맞춘다**는 결론에 도달 (AUC가 베이스라인 근처)
- 여기서 지표를 포장하는 대신, 점수제를 **"예측기"가 아니라 "투명한 현황 체크리스트"** 로 재정의.
  기대수익의 원천을 재료(공시·뉴스) · 밸류에이션 · 리스크 관리 · 근거 공개로 옮김
- RF·XGBoost·LSTM을 같은 분할에서 비교하고 **확률 보정 후 앙상블**, 종목별로 백테스트 베이스라인을
  못 이기면 **신뢰도를 낮추고 경고**를 띄움 — 과신을 막는 게 설계 목표
- FDR·네이버 증권·DART 공시·NASDAQ 등 **다중 소스 파이프라인** (소스 장애 시 백업·캐시로 무중단)
- 관심 종목 급등락·공시·뉴스를 3분 주기로 감지해 **텔레그램 실시간 알림**
